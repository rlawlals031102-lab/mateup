# 스터디버디 (studybuddy.)

> 1주일 단위 1:1 스터디 메이트 매칭 플랫폼 — 메이트업 MateUp · 국민대학교 창업동아리

혼자 하는 공부는 미뤄도 아무도 모르기 때문에 쉽게 무너집니다.
스터디버디는 "같은 시간에 함께 시작한다"는 약속 하나로 두 사람을 연결하고, 출석·공부시간 기록과 약속 보증금으로 그 약속이 지켜지게 만듭니다.

## 실행 방법

Node.js 22.13 이상이 필요합니다. 로컬에서는 Node 내장 `node:sqlite`를 써서 별도 DB 설치가 필요 없고, 실서비스는 Supabase(PostgreSQL)를 씁니다.

```bash
npm install
npm run demo     # 데모 모드 (추천): SQLite + 데모 메이트, 시간과 상관없이 출석, 주간 즉시 마감 버튼
npm start        # 일반 모드: SQLite, 약속 시작 30분 전 ~ 종료 시각에만 출석 가능
npm run dev      # 데모 모드 + 파일 변경 시 자동 재시작
npm run dev:db   # .env.local 의 DATABASE_URL(Supabase, 실서비스 DB!)에 접속해서 실행
npm test         # 매칭·출석·정산 테스트 (SQLite와 PostgreSQL 모두)
```

브라우저에서 http://localhost:3000 을 열고 회원가입하면 됩니다. 모바일 화면 기준으로 디자인되어 있습니다.

환경 변수: `PORT` (기본 3000), `DB_FILE` (기본 `data/studybuddy.db`), `DEMO_MODE=1` (`--demo`와 동일), `DATABASE_URL` (있으면 SQLite 대신 PostgreSQL 사용)

데이터를 초기화하려면 서버를 끄고 `data/` 폴더를 지우세요.

## 서버 없이 HTML 파일 하나로 체험하기

```bash
npm run build:standalone
```

`dist/studybuddy-demo.html` 이 만들어집니다. 이 파일만 더블클릭하면 서버 없이 모든 기능(데모 모드)을 쓸 수 있고, 다른 사람에게 파일로 보내도 됩니다.

- 서버 로직(`server/service.js`)을 그대로 브라우저에서 실행하고, DB는 SQLite WASM(sql.js)으로 대체합니다. 관련 코드는 `standalone/`에 있습니다.
- 데이터는 그 브라우저(localStorage)에만 저장되어 다른 사람과 공유되지 않습니다. 마이페이지의 "데모 데이터 모두 지우기"로 초기화할 수 있습니다.
- 화면이나 로직을 고친 뒤에는 이 명령을 다시 실행해야 파일에 반영됩니다.

## 실서비스 배포 (Vercel + Supabase)

GitHub `main` 브랜치에 push하면 Vercel이 `npm run build:vercel`을 실행해 배포합니다. (`vercel.json`)

| 주소 | 내용 |
| --- | --- |
| `/` | 실서비스 화면 (`public/`) — 실제 사용자끼리 매칭 |
| `/api/*` | 서버 API — `api/index.js` 서버리스 함수(서울 `icn1`)가 `server/app.js`를 실행 |

- DB: Supabase PostgreSQL(서울 `ap-northeast-2`). Vercel 환경 변수 `DATABASE_URL`에 **Transaction pooler(포트 6543)** 주소를 넣습니다. 테이블은 첫 실행 때 자동으로 만들어지고, 모든 테이블에 RLS가 켜져 Supabase 공개 API로는 접근할 수 없습니다.
- 주간 정산: Vercel Cron이 매일 00:00(KST)에 `/api/cron/settle`을 호출합니다. 사용자가 앱을 열 때도 정산을 확인합니다. 환경 변수 `CRON_SECRET`을 넣으면 크론 호출만 허용합니다(선택).
- 실서비스에는 데모 기능(시간 무관 출석, 즉시 마감)이 없습니다. 데모 버전은 배포하지 않습니다(`npm run build:standalone`으로 HTML 파일만 만들 수 있음).
- 가입·로그인은 국민대 메일(@kookmin.ac.kr)만 가능하고, 가입·비밀번호 찾기는 메일 인증번호로 확인합니다. Vercel 환경 변수 `GMAIL_USER`, `GMAIL_APP_PASSWORD`(Gmail 앱 비밀번호)가 필요합니다.
- 날짜 계산은 서버 위치와 상관없이 한국 시간(KST) 기준입니다. (`server/time.js`)

## 기능 (기획서 → 구현)

| 기획서 | 구현 내용 |
| --- | --- |
| **매칭 신청** — 요일·시간, 장소, 교류 방식(체크형·대화형·사교형) | 이번 회차 화·수·목마다 18~21시 중 1시간 칸(18–19·19–20·20–21시)을 여러 개 고른다. 조건이 맞고 겹치는 칸이 있는 메이트와 즉시 1:1 연결되고, 겹치는 칸이 그날 약속이 된다. 없으면 대기열 |
| 홈 '이번 회차 내 약속' | 시간표 대신 화·수·목 날짜별 카드(매칭됨 · 메이트 찾는 중 · 비어 있음)를 위에서 아래로 쌓아 보여 준다 |
| **약속 보증금 (선택, 계좌이체)** | 신청 때 5천/1만/2만 원을 운영진 계좌로 입금 → 운영진이 운영자 화면에서 입금 확인 → 매칭 대기열. 약속을 모두 지키면 환급 · 못 지키고 메이트는 지켰으면 메이트에게 보상 · 둘 다 못 지키면 운영진에게 귀속 · 중도 종료하면 메이트에게 보상. 이체할 금액은 앱이 계산해 운영자 화면에 보여 준다 |
| **약속 이행** — 출석·공부시간 기록 | 매칭되면 1주일치 약속이 자동 생성. 메이트의 QR을 스캔(또는 6자리 코드 입력)하거나 직접 출석. 출석 후 타이머로 공부시간 기록 |
| **주간 리포트와 재매칭** | 주간이 끝나면 자동 정산 후 리포트(출석률·공부시간·보증금 결과). "계속하기"를 둘 다 고르면 다음 주 약속이 바로 생성되고, 한 명이라도 "새 메이트"를 고르면 종료 |
| 화면 스케치 — 매칭중 화면 | 메이트 프로필, 예정된 약속, 현장 출석 확인(QR), 이번주 출석 그리드, 하단 탭(홈·매칭중·채팅·마이페이지) |
| (추가) 채팅 · 마이페이지 | 메이트와 1:1 실시간 채팅(사진 보내기), 프로필 사진·태그 수정, 보증금 내역, 지난 스터디 기록 |
| (추가) 운영자 화면 `#/admin` | 탭 4개. **현황**: 전환 단계(방문→가입→신청→매칭→출석) · 방문 통계 · 가입자(전화번호 가림) · 인증메일 · 신청 · 매칭 / **돈**: 입금 확인 · 환급/보상 이체 목록 / **메일**: 인증 메일 도움 요청 처리 · 발송 기록 / **채팅**: 매칭별 채팅 기록(열람 기록이 남음) |

### 매칭 규칙 (`server/service.js` → `compatibility`)

두 신청이 아래를 모두 만족하면 매칭되고, 후보가 여럿이면 겹치는 요일·스타일·시간이 많은 쪽을 우선합니다.

- 겹치는 장소 1개 이상 (장소는 여러 개 고를 수 있고, 겹치는 장소가 여럿이면 강의실을 '채팅으로 정하기'보다 먼저 고름)
- 겹치는 요일 1개 이상 → 겹치는 요일이 약속 요일이 됨
- 겹치는 시간 1시간 이상 → 겹치는 구간이 약속 시간이 됨
- 공통 공부 스타일 1개 이상
- 보증금 사용 여부가 같을 것 (금액이 다르면 낮은 금액에 맞추고 차액은 즉시 반환)

### 데모 메이트

매칭을 기다리는 데모 메이트 2명(`server/seed.js`)이 있어 혼자서도 전체 흐름을 체험할 수 있습니다(데모 모드에서만, 공용 데모 계정하고만 매칭). 화면에는 "데모 메이트"로 표시되고, 사용자가 출석하면 함께 출석하고, 채팅에 답장하며, 리포트에서 항상 "계속하기"를 고릅니다. 목록에서 빠진 예전 데모 메이트는 실행할 때 자동으로 정리됩니다(매칭 기록이 있으면 기록용으로만 남김).

| 이름 | 날짜 · 시간 | 장소 | 스타일 | 보증금 |
| --- | --- | --- | --- | --- |
| 김저녁 | 이번 회차 모든 칸 | 지정 강의실 (경상관 102A) | 체크형·대화형·사교형 | 없음 |
| 김대화 | 이번 회차 모든 칸 | 채팅으로 정하기 | 체크형·대화형·사교형 | 없음 |

장소: 채팅으로 정하기, 지정 강의실 (경상관 102A) — 여러 개 고를 수 있음 (`server/options.js`)

## 회차 바꾸기

`server/options.js`의 `STUDY_PERIOD.dates`를 다음 회차 화·수·목 날짜로 바꾸고 배포한다. (지금: 11/10·11·12, 18~21시) 로그인 화면 소개 팝업의 일정 문구도 여기서 자동으로 만들어진다.

## 새 기능 설정 (Vercel 환경 변수)

| 환경 변수 | 필수 | 하는 일 |
| --- | --- | --- |
| `ADMIN_EMAILS` | 운영자를 더 두려면 | `server/options.js`의 `ADMIN_EMAIL`은 항상 운영자이고, 여기에 운영진 메일을 더 적는다 (쉼표로 여러 명). 국민대 메일이 아니어도 된다(개인 Gmail 가능). 이 메일로 회원가입·로그인하면 운영자 화면을 쓸 수 있다. 바로가기 주소: `/admin` |
| `DEPOSIT_ACCOUNT` | 보증금을 받으려면 | 신청 화면에 보여 줄 운영진 계좌 문구. 예: `국민은행 123456-01-234567 (예금주 김지민)`. 없으면 보증금 선택이 안 보인다 |
| `SUPABASE_URL`, `SUPABASE_ANON_KEY` | 실시간 채팅을 쓰려면 | Supabase 대시보드 → Project Settings → API의 Project URL과 anon(public) 키. Realtime 설정에서 공개 채널(Allow public access)을 허용해야 한다 |
| `GMAIL_USER_2`, `GMAIL_APP_PASSWORD_2` | 선택 | 예비 Gmail 계정. 첫 계정이 막히거나 한도에 걸리면 이 계정으로 인증 메일을 보낸다 |
| `REALTIME_SECRET` | 선택 | 실시간 채널 이름을 만드는 비밀값. 없으면 DATABASE_URL로 만든다 |

새 테이블(visits, photos, money_logs, email_logs, email_help, admin_logs)과 열은 배포 후 첫 요청 때 자동으로 만들어진다.

### 인증 메일이 가끔 안 오던 원인과 대응 (`server/mailer.js`, `requestEmailCode`)

| 원인 (코드 분석) | 대응 |
| --- | --- |
| SMTP 연결에 시간 제한이 없어 느릴 때 서버 함수가 먼저 끝날 수 있음 | 연결 7초·응답 10초 제한, Vercel 함수 최대 30초(`vercel.json`) |
| 한 번 실패하면 재시도 없음 (Gmail 일시 거절·한도·로그인 차단) | 계정마다 2번 시도, 예비 계정으로 한 번 더 |
| 보내기에 실패해도 인증번호가 남아 60초 동안 다시 받을 수 없었음 | 실패하면 그 번호를 지워 바로 다시 받을 수 있게 |
| 늦게 온 메일의 번호를 넣으면 "맞지 않아요" (마지막 번호만 인정) | 10분 안에 받은 번호는 모두 인정 |
| 실패 기록이 없어 원인을 알 수 없었음 | `email_logs`에 성공·실패·오류 내용 기록, 운영자 화면에서 확인 |
| 그래도 메일이 안 오면 가입할 방법이 없었음 | "메일이 안 와요" → 운영진이 본인 확인 후 운영자 화면에서 인증번호를 만들어 문자로 전달 |

## 구조

```
api/
  index.js     Vercel 서버리스 함수 (실서비스 API)
server/
  index.js     로컬 서버 시작, 데모 메이트 생성, 주간 자동 정산 스케줄
  app.js       Express 라우트 (REST API + 정적 파일 + 크론)
  service.js   핵심 로직: 인증, 매칭, 출석, 정산, 재매칭, 채팅, 포인트 (동시 접속 안전)
  db.js        DB 공통 인터페이스, 스키마, SQLite 드라이버
  db-pg.js     PostgreSQL 드라이버 (Supabase / 테스트용 PGlite)
  options.js   장소·스타일·보증금 옵션
  seed.js      데모 메이트
  time.js      날짜 유틸 (KST 고정, 테스트에서 시간 고정 가능)
public/        모바일 웹 프론트엔드 (빌드 없는 바닐라 JS)
standalone/    서버 없는 HTML 데모용 브라우저 어댑터
scripts/       빌드 스크립트 (단독 HTML, Vercel)
test/          node:test 테스트 (SQLite·PostgreSQL 양쪽에서 실행)
```

## 참고 / 한계

- 보증금은 **가상 포인트**입니다. 실제 결제를 붙이려면 PG 연동(예치·환불·정산)이 필요합니다.
- 출석 QR은 약속마다 하나의 코드를 두 사람이 공유하는 방식이라, 같은 장소에 있다는 것을 강하게 보장하지는 않습니다. 실서비스에서는 시간에 따라 바뀌는 코드나 위치 확인을 더하는 것을 권장합니다.
- 카메라 QR 인식은 `BarcodeDetector`를 지원하는 브라우저(안드로이드 Chrome 등)에서 동작하며, 그 외에는 코드 입력으로 출석합니다. 카메라는 `localhost` 또는 HTTPS에서만 사용할 수 있습니다.
- 채팅은 Supabase Realtime이 설정되어 있으면 실시간, 아니면 3초 간격으로 새 메시지를 확인합니다.
- 사진은 화면에서 긴 변 1280px JPEG로 줄인 뒤 DB(photos 테이블)에 저장합니다. 사용자가 많아지면 Supabase Storage로 옮기는 것을 권장합니다.
- 보증금은 실제 돈이 오가므로 운영 전에 학교·전문가에게 확인하세요. 앱은 계산과 기록만 하고, 이체는 운영진이 직접 합니다.
- 개인정보처리방침(학과·전화번호·환급 계좌·채팅 열람)은 아직 없습니다.
